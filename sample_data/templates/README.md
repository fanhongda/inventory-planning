# 物料替代表 · substitutions

计划员维护的那一张表：**哪两个物料号是同一个东西**。

这张表是这条信息唯一的来源。交易数据里没有任何东西能说明 7100014 和 7100015 是一个
料——所以它只能是声明的。管道不会去猜，也不会从"一个号归零、另一个号起量"里推断关系，
因为漏掉一对只是维持现状，而**编错一对会把两个不相干物料的库存和历史加在一起，跑出一份
完整、自洽、且错误的报告，中间没有任何一步会报错**。

同理，**只有这张表能触发合并**。item master 上的后继物料列会被读到，但只输出成提议；
路由分数不够高的文件不会被当成这张表用。

---

## 最简形式

两列就够了。存成 CSV 或 Excel，和其它文件一起交给管道，会自动识别。

```csv
old_sku,new_sku
7100014,7100015
```

## 完整形式

`substitutions.csv` 是可以直接复制去改的模板。六个列：

| 列 | 必填 | 说明 |
|---|---|---|
| `old_sku` | ✅ | 被停用的号。它在**所有**文档里的每一次出现都会被改写成 `new_sku` |
| `new_sku` | ✅ | 留下来的号。计划跑在这个号上 |
| `relation` | | `supersede`（完全替代，合并数据）或 `phase`（并存，只标注不合并）。**不填按 supersede 处理**，运行时会提示这是假设的 |
| `ratio` | | 一个旧号等于几个新号。`qty_new = qty_old × ratio`，默认 1。**包装或计量单位变了就必须填**——不填会差一个数量级，而且没有任何东西会发现 |
| `effective_date` | | 切换生效日。合并本身不需要它，但它是运行时**核对这个声明**的唯一依据：旧号在这个日期之后还在交易会被报出来 |
| `rationale` | | 为什么这两个号是同一个料。解析器不强制，规矩强制——三个月后没人记得是谁定的、依据是什么，而合并物料号是对这套系统能做出的最重的一个断言 |

表头认中文、英文和 SAP 导出的写法：`旧物料号` / `Old Material` / `Predecessor` /
`Superseded Material`，`新物料号` / `New Material` / `Successor` / `Follow-up Material`
/ `NFMAT` 都能识别。

---

## 表里能表达的四种情况

模板里各有一行：

**1 · 完全替代**（最常见）
```
7100014,7100015,supersede,1,2026-03-01,...
```
两个号的库存、订单、历史全部相加，保留新号。

**2 · 改号同时换了包装**
```
4190-6002,4190-6010,supersede,10,2026-01-15,...
```
数量 ×10，单价 ÷10，总金额不动。

**3 · 并存（phase-in / phase-out）**
```
ULFMCV224151,ULFMCV224160,phase,,2026-02-01,...
```
读到、计数、**不合并**。目前仅此而已——phase 的计划逻辑还没做，见 `TODO.md`。

**4 · 链式和多对一**
```
7781001,7781002,supersede,1,2025-06-01,第一次改号
7781002,7781003,supersede,1,2026-04-01,第二次改号
8890011,8890099,supersede,1,2025-11-01,两个旧号
8890012,8890099,supersede,1,2025-11-01,合并到一个现行号
```
链会自动收敛到最终号（7781001 → 7781003），`ratio` 沿链相乘。多对一是正常的。

**一对多会被整对丢弃并报告**——一个号有两个后继是拆分，不是改号，哪笔交易归哪个是关于
交易的问题，没有任何规则能替你决定。成环同理。

## 两个写文件时的坑

- **`rationale` 里用全角逗号「，」。** CSV 里的半角逗号会被当成分隔符，整行读不进来。
  用 Excel 存就没这个问题。
- **日期尽量写 ISO（`2026-03-01`）。** 只有一行、又写成 `01.03.2026` 时，没有任何办法
  判断是 3 月 1 日还是 1 月 3 日。行数多起来管道能从数据里推断出来，但一行的表推断不了。

## 从 SAP 直接导，不用手敲

SAP 的物料淘汰功能已经维护了这些字段（MARC 层，工厂视图）：

| 字段 | 含义 |
|---|---|
| `MARC-NFMAT` | 后继物料 |
| `MARC-AUSDT` | 失效日期 |
| `MARC-KZAUS` | 淘汰标识 |

**先去确认有没有人维护过**——有的话导出来就是这张表的全部内容，比手敲可靠得多。

如果这些列跟在 item master 里一起交过来，运行时会把它们读出来、整理成上面这个格式打印
出来，但**不会执行**：那份 master 是为了提供交期和 MOQ 交过来的，`NFMAT` 是在淘汰决策
那一刻维护、多年后才被读到的字段，很容易过期，而且没有人为这次运行选择过它。把打印出来
的内容核对一遍存成文件交回来，就成了合并需要的那个明确动作——手敲还是省掉了。
